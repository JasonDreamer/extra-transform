# 仕組み

[English](how-it-works.md) | 日本語

## 合成の仕方

レイヤーの値は、ドライバーでオブジェクト標準の Delta Transform（`delta_location`、`delta_rotation_euler`、`delta_rotation_quaternion`、`delta_scale`）に書き込んでいます。最終的な変換は Blender 自身が普段どおりに計算するので、レイヤーが1枚なら標準の Delta と結果が完全に一致します。

レイヤーが複数ある場合は、チャンネルごとに次のように合成します。

| チャンネル | 合成 |
| --- | --- |
| 位置 | 全レイヤーの和 |
| スケール | 全レイヤーの積（軸ごと） |
| 回転 | 回転行列（クォータニオンモードではクォータニオン）の積。後のレイヤーほど左から掛かります |

合成はチャンネルごとです。外側のレイヤーの回転やスケールは、内側のレイヤーの位置には影響しません。親子の Empty を重ねた場合とはここが違います。

回転はオブジェクトの回転モードで読みます。回転モードを変えるとドライバーを作り直します。軸角度モードには Delta の回転がないため、回転は合成しません（位置とスケールは合成します）。

無効にしたレイヤーは合成から外れます。

## データの置き場所

レイヤーの値は、オブジェクトのカスタムプロパティとして `Extra 1 Location`、`Extra 2 Euler Rotation` のような名前で持っています。番号はスタック内の位置で、並べ替えると名前とキーフレームのパスが振り直されます。キーを打ったチャンネルは、グラフエディターで Object Transforms グループに入ります。

アドオンのプロパティ（`bpy.props`）をドライバーから読むと依存関係のループになるため、値はカスタムプロパティに置いています。

## ドライバー

どのドライバーもレイヤーの値を直接読み、標準の Delta のチャンネルに書き込みます。ドライバーの結果を別のドライバーで読む、という連鎖はしていません。Blender 5.2 ではマルチスレッド評価の際、カスタムプロパティに書くドライバーの結果がまれに失われるためです。

- 位置: SUM ドライバー
- スケール: `a*b*c...` の式（レイヤー数の上限 100 はこの式の長さで決まっています）
- 回転（1枚）: 入力をそのまま渡します
- 回転（2枚以上）: アドオンが `bpy.app.driver_namespace` に登録する関数 `extra_transform_rotation` で合成します

回転レイヤーが2枚以上あるファイルを、アドオンを入れていない環境で開くと、この関数が無いため回転が正しく出ません。位置とスケールは普通の式なので、アドオンが無くても動きます。

## 標準の操作との関係

Ctrl+A、Alt+G/R/S、「トランスフォームをデルタに」などは標準の Delta に直接書き込みます。そのままだと次の評価でドライバーに上書きされるので、アドオンは評価のたびに Delta の値を覚えておき、次の評価の前に値が変わっていたら外からの書き込みとみなして、レイヤーに反映し直します。

- 初期値（位置 0、回転 0、スケール 1）が書かれたチャンネルは、全レイヤーのそのチャンネルをリセットします
- それ以外の値は、内側のレイヤーの合成結果を差し引いて、一番外側のレイヤーに入れます

アンドゥやファイルの読み込みの際は、覚えている値を破棄します。

## 既存の Delta

Delta にすでに値やアニメーション、ドライバーがあるオブジェクトでレイヤーを追加すると、その内容は「Delta」という名前の1枚目のレイヤーに移ります。
