# 仕組み

[English](how-it-works.md) | 日本語

## 1. 概要

各レイヤーの値をドライバー経由で Blender の Delta トランスフォーム（`delta_location` など）に集約する仕組みです。レイヤーが1枚の場合、計算結果は Blender 標準の Delta と同一です。

## 2. 合成ルール

各チャンネルは独立して合成されます。外側（上位）のレイヤーで回転を行っても内側（下位）のレイヤーの位置には影響しません（Empty の親子構造とは異なります）。

| チャンネル | 合成方法 | 備考 |
| --- | --- | --- |
| 位置 | 加算 | |
| スケール | 乗算 | 軸ごとに計算 |
| 回転 | 行列（またはクォータニオン）の乗算 | 外側のレイヤーが左から掛かる |

- **回転モード**: オブジェクトの回転モードに従います。モード変更時はドライバーを再生成します。
- **軸角度 (Axis-Angle)**: Delta に回転の対応がないため、位置とスケールのみ合成します。

## 3. データの保存構造

- レイヤーの値はオブジェクトのカスタムプロパティ（例: `Extra 1 Location`）に保存されます。
- 番号はスタック順に対応し、並べ替えるとプロパティ名とキーフレームのパスを再割り当てします。
- `bpy.props` を使用しない理由は、ドライバー参照時の評価ループ（循環依存）を防ぐためです。

## 4. ドライバー仕様とマルチスレッド対策

すべてのドライバーは 1 段構成（レイヤー値を直参照して Delta へ直接出力）です。多段構成にすると、Blender 5.2 のマルチスレッド評価で書き込み漏れが発生します。

- **位置**: SUM ドライバー
- **スケール**: `a*b*c...` の乗算式（レイヤー上限 100 は数式文字列の長さ制限による）
- **回転（1枚）**: 入力をそのまま通過
- **回転（2枚以上）**: アドオンが登録するカスタム関数 `extra_transform_rotation` で計算

## 5. 標準操作（Ctrl+A / Alt+G, R, S）への追従

標準のトランスフォーム操作は Delta へ直接書かれるため、以下の処理で各レイヤーへ書き戻します。

1. 毎評価時に Delta の値をキャッシュし、変更を検出。
2. クリア（0 / スケール 1）されたチャンネルは、全レイヤーの値を初期化。
3. それ以外の変更は、内側レイヤーの値を差し引いた値で一番外側のレイヤーを置き換え。
4. Undo 時およびファイル読み込み時は、キャッシュをリセット。

## 6. 注意事項

- **既存 Delta 値の扱い**: Delta に値・アニメーション・ドライバーが存在する状態で追加した場合、既存データは自動生成される「Delta」レイヤーへ移動します。
- **アドオン未導入時の挙動**:
  - 位置・スケール: 正常に動作します。
  - 回転（2枚以上）: カスタム関数が存在しないため、評価結果がずれます。
